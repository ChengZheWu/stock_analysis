# 台股動能選股系統

以技術面動能為核心的選股與回測系統，涵蓋上市與上櫃股票，
每日盤後產生推薦名單，並可透過 Telegram 推播。

## 策略邏輯

| 階段 | 規則 |
|---|---|
| 大盤濾網 | 加權指數在 200 日均線之上才開新倉 |
| 個股篩選 | Minervini 趨勢模板：股價 > 50MA > 150MA > 200MA、200MA 上升中、距 52 週低點 +30% 以上、距 52 週高點 -25% 以內 |
| 排名 | 12 個月（扣除最近 1 個月）、6 個月、3 個月報酬加權後，再除以年化波動度 |
| 進場 | 突破前 20 日最高價一檔，以停損買單成交；單日最多 10 筆，同一檔最多買進 4 次（成本以均價計） |
| 出場 | 初始停損 2.5 ATR、移動停損 4.0 ATR（取較高者），或收盤跌破 50 日均線。整檔一次出清 |

只要移動停損未被觸及就續抱，因此強勢股可以長期持有。

## 資料來源

| 用途 | 來源 | 說明 |
|---|---|---|
| 歷史與每日行情 | 證交所、櫃買中心 | 每日全市場報表，逐日回補十年；每天僅需 2 次請求 |
| 除權息、減資 | 證交所、櫃買中心 | 提供事件前收盤價與參考價，用於計算還原因子 |
| 分割、面額變更 | FinMind | 批次資料集 |
| 加權指數 | FinMind | 大盤濾網用 |
| 0050 基準 | Yahoo Finance | 單一標的，不佔用 API 額度 |

股價一律經過還原處理，除權息不會干擾指標判斷。

### 為何以官方每日報表為主要來源

改用官方逐日快照解決了三個問題：

1. **開盤價正確**。FinMind 對股票的興櫃期間會用前一日均價填充開盤價，導致開盤價高於當日最高價。在測試的 560 檔中有 47 檔出現此問題，其中 4 檔超過八成的資料列受影響。
2. **自動排除興櫃期間**。興櫃採議價交易，回測買賣興櫃股並不切實際。
3. **存活者偏差涵蓋更完整**。逐日快照天然包含當時在市、後來下市的股票，不必依賴未必完整的下市清單。

## 安裝

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

在專案根目錄建立 `.env`：

```
FINMIND_TOKEN=你的token
TELEGRAM_BOT_TOKEN=你的bot token     # 推播才需要
TELEGRAM_CHAT_ID=你的chat id         # 推播才需要
```

## 使用方式

```bash
# 一、首次建立歷史資料
.venv/bin/python scripts/backfill.py market      # 加權指數、分割、面額變更
.venv/bin/python -m src.corporate                # 除權息、減資（約 15 分鐘）
.venv/bin/python scripts/backfill_twse.py        # 十年逐日行情（約 90 分鐘）

# 二、回測
.venv/bin/python scripts/run_backtest.py           # 10 年、5 年、1 年
.venv/bin/python scripts/run_backtest.py 10y       # 指定單一窗口

# 三、每日盤後推薦
.venv/bin/python scripts/daily.py                  # 輸出到終端機
.venv/bin/python scripts/daily.py --push           # 並推播到 Telegram

# 四、測試
.venv/bin/python -m pytest tests/ -v
```

抓取中斷可直接重新執行，已完成的日期會自動略過。

## 回測的時序假設

- 第 t 日收盤後計算訊號與觸發價，第 t+1 日才可能成交，不使用未來資訊。
- 進場模擬停損買單：當日最高價觸及觸發價才成交，成交價取 `max(開盤價, 觸發價)`。
- 出場模擬停損賣單：當日最低價觸及停損價才成交，成交價取 `min(開盤價, 停損價)`。
- 同一日同時觸及進出場價時，一律採不利假設。
- 成本包含手續費（含折扣與最低收費）、賣出證交稅，以及滑價。
- 價格對齊台股升降單位。

## 回測結果（2016-09 ~ 2026-09，初始 50 萬元）

對照兩個基準：**0050**（大型股，含息）與**大盤報酬指數**（全市場，含息）。
策略使用還原股價，報酬同樣含息，三者基礎一致。

| 窗口 | 標的 | 年化報酬 | 年化波動 | 夏普值 | 最大回撤 | 期末資金 |
|---|---|---|---|---|---|---|
| 10y | **策略** | **35.01%** | 23.47% | **1.44** | -33.57% | **1,004 萬** |
| 10y | 0050 | 23.83% | 20.30% | 1.19 | -33.83% | 423 萬 |
| 10y | 大盤 | 21.84% | 18.61% | 1.19 | -28.55% | 360 萬 |
| 5y | **策略** | **39.48%** | 25.46% | **1.48** | **-27.46%** | **264 萬** |
| 5y | 0050 | 29.47% | 23.35% | 1.26 | -33.83% | 182 萬 |
| 5y | 大盤 | 26.13% | 21.38% | 1.23 | -28.47% | 160 萬 |
| 1y | 策略 | 58.90% | 39.73% | 1.41 | -26.59% | 79 萬 |
| 1y | 0050 | **92.00%** | 28.93% | 2.49 | -15.37% | 96 萬 |
| 1y | 大盤 | 83.37% | 27.25% | 2.45 | -15.72% | 92 萬 |

交易次數依序為 1,554 / 705 / 177 筆，勝率 28.7% / 29.2% / 26.0%，
獲利因子 1.85 / 1.88 / 1.63，平均持有 37 / 39 / 36 個交易日。

### 解讀

- **10 年與 5 年都勝過兩個基準，且風險調整後也較佳**。5 年窗口的最大回撤
  （-27.46%）甚至小於 0050 的 -33.83%，夏普值 1.48 對 1.26。
- **1 年落後**。2025–2026 的漲幅高度集中在權值股：該期間近九成個股跑輸 0050，
  2025 年全市場中位數報酬甚至為負。0050 為市值加權，等於直接重壓少數贏家；
  本策略持有十餘檔中小型股，結構上難以跟上這種行情。
- **勝率低但獲利因子高**。平均獲利 24.72%、平均虧損 -8.33%，接近三倍。
  獲利高度集中於少數部位（10 年最大單筆 +466%，最長持有 257 個交易日），
  這是順勢策略的常態，也代表結果對個別大贏家敏感。
- **輸家出場快、贏家抱得久**。依持有長短分組可見，持有 10 天內的交易整體為虧損，
  持有超過 120 天者全數獲利——並非「抱久會賺」，而是賺錢的部位才不會觸發停損。

## 已知限制

- **無成交量門檻**：回測可能買到實際難以成交的冷門股。以 50 萬本金影響有限，
  但資金規模放大後必須加上，否則回測會高估。
- **持股檔數不設上限**：實際檔數由資金決定，50 萬本金約同時持有 15 檔。
- **未考慮漲停買不到**：漲停鎖死時實際上無法成交，回測仍假設可以。
  已用貼近突破價的條件排除最極端的情況，但無法完全避免。
- **跌破均線一律整檔出清**：亦可改為只減碼一半（`scale_out=True`），
  剩餘部位續抱至觸及停損。回測顯示 10 年年化 34.92% 對 35.01%、
  5 年 39.60% 對 39.48%、1 年 66.99% 對 58.90%——一勝兩平，差異在雜訊範圍內，
  不足以作為採用依據，故維持整檔出清。
- **進場當日不檢查停損**：日 K 無法得知當日最低價出現在突破之前或之後，
  預設視為出現在突破前（此時尚未持倉）。10 年有 21.5% 的交易受此假設影響；
  以 `same_day_stop=True` 跑最悲觀的下界，10 年年化由 35.01% 降為 34.67%、
  5 年由 39.48% 降為 36.73%，結論不變。真實值介於兩者之間。
- **獲利集中於少數交易**：前 10 筆貢獻 76% 的損益，結果對個別大贏家敏感。
- **參數未經樣本外驗證**：目前參數取自文獻標準值，`ENTRY_MAX_ATR_GAP`
  依可執行性選定而非回測報酬。若日後調整參數，應保留最近數年作為樣本外驗證。
- **存活者偏差已大幅降低但非零**：逐日快照涵蓋期間內下市的 156 檔股票，
  惟仍可能遺漏極少數情況。
- **策略特性**：動能策略在多頭表現較好，急轉市會明顯回撤，屬於輔助工具。

## 部署到伺服器

開發與回測在本機進行，伺服器只負責每天盤後產生訊號。兩者需要的資源差很多：

| | 本機 | 伺服器 |
|---|---|---|
| 工作 | 開發、回測、重建面板 | 每日訊號 |
| 峰值記憶體 | 1.2 GB | **750 MB** |
| 資料量 | 約 330 MB（含十年逐日報表） | **23 MB** |
| 每次耗時 | 重建約 25 秒 | 約 19 秒 |

伺服器不需要完整面板（約 150 MB）與十年逐日報表（約 155 MB），
只要近期面板（450 個交易日）等約 23 MB。近期面板採滾動視窗，不會無限成長。

因此 **2 GB 記憶體的小型主機即可**，即使同時跑其他程式也有餘裕。

### Oracle Cloud Always Free

Always Free 的 Ampere A1（ARM）方案為 4 OCPU / 24 GB RAM，遠超需求且永久免費。
注意另一種 Always Free 的 AMD micro 只有 1 GB RAM，**不足以執行本專案**。

建立 instance 時的設定：

- Image：Canonical Ubuntu 24.04
- Shape：`VM.Standard.A1.Flex`，OCPU 設 2、Memory 設 12 GB（留餘裕給其他用途）
- Boot volume：50 GB 以上
- 記得下載 SSH 私鑰

ARM 架構不影響本專案，所需套件（pandas、numpy、pyarrow）均有 aarch64 版本。

若建立時出現 "Out of host capacity"，表示該區域 ARM 資源已滿，可換區域或稍後重試。

### 部署步驟

```bash
# ── 本機：先建好資料 ──
bash deploy/backfill.sh                    # 約 2 小時，只需做一次

# ── 打包程式碼（不含資料與虛擬環境，約 400 KB）──
tar czf stock.tar.gz --exclude=.venv --exclude=data --exclude=.git .
scp -i <私鑰> stock.tar.gz ubuntu@<伺服器IP>:~/

# ── 伺服器：建置環境 ──
ssh -i <私鑰> ubuntu@<伺服器IP>
mkdir -p stock_analysis && tar xzf stock.tar.gz -C stock_analysis
cd stock_analysis
bash deploy/setup.sh
nano .env                                  # 填入 token

# ── 本機：同步資料（約 23 MB）──
bash deploy/sync.sh ubuntu@<伺服器IP> <私鑰>

# ── 伺服器：驗證並設定排程 ──
.venv/bin/python scripts/daily.py --no-update
bash deploy/install_cron.sh
```

伺服器**不需要**執行 `backfill.sh`——歷史資料在本機建好後同步過去即可。

日後策略或參數有調整時，在本機重跑回測確認，再重新 `sync.sh` 同步資料、
`scp` 更新程式碼即可。

### 排程與每日資料維護

`install_cron.sh` 會設定週一至週五 15:30 執行（台股 13:30 收盤，
官方報表約 14:00–15:00 齊備，留有緩衝）。非交易日不會產生訊號，也不會推播。

**伺服器每天會自行維護資料，不需要重複同步**：

1. 向證交所與櫃買抓取最新行情（每天約 2 次請求）
2. 追加到近期面板，並重算近期有除權息或減資的股票
3. 更新近三個月的公司行為
4. 產生訊號、寫入紀錄簿、推播

`sync.sh` 只在兩種情況需要執行：初次部署，以及本機重建面板後
（例如調整了還原邏輯或補抓了歷史資料）。

排程失敗時會推播錯誤訊息；連續超過 15 天沒有新資料也會通知，
避免資料來源或排程異常時無人察覺。

### 注意事項

- **`journal.db` 是你的買賣紀錄**，存放於 `data/results/`，務必定期備份。
- `.env` 不在版控內，需手動複製，並設為 `chmod 600`。
- Oracle 預設會封鎖對外連線以外的埠，本專案只需對外連線，無需開埠。
- 重複執行同一天的排程不會產生重複紀錄（`rec_date` 強制隔日才結算）。
